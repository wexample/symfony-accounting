## Décisions prises seul, à juger à l'usage

- accounting est refait de zéro. Les entités appartiennent au package (`Ledger` pour le dossier, `Party` pour le tiers), plutôt que de passer par `resolve_target_entities`. Le lien avec l'application passe par `externalReference`, peut-être un pattern à généraliser, à juger à la première intégration dans une vraie app.
- Les parsers FR (LBP, CA) et le RIB vivent dans accounting-fr, et PhpSpreadsheet n'est requis que par -fr.

## Pièges rencontrés
- `yarn add` dans le conteneur node retire les `@wexample/js-*` liés : relancer le conteneur les relie. Le watch webpack se lance à part (`yarn watch` dans le conteneur node) ; un redémarrage du conteneur le coupe.
- Avec `buildCache: true`, webpack croit immuables les packages js-* liés : vider `node_modules/.cache/webpack` après les avoir modifiés.
- js-helpers est compilé par les apps avec une cible inférieure à ES2020 : pas de littéraux BigInt.
- ~~Le loader ne donnait les traductions d'une vue qu'à sa première instance sur la page~~ : corrigé dans symfony-loader (036e31f). Le contournement de media-ds (`media_picker_labels()`, libellés en props) peut repasser en `trans_js` ; laissé tel quel, un autre agent travaillait sur media.
- Mercure récent : le bloc `mercure` du Caddyfile exige `protocol_version_compatibility 8` ou un bloc `issuer` ; template de symfony-live corrigé (19ee6fd), le hub de MOJOE démarre.
